# Dev Workstation Profile

Machine posture profile for **dev workstations**: full write access and responsibility for prod
deploys. Sibling: `.claude/machines/analysis.md` (read-only box), never loaded here. This file
**only adds** to the root `CLAUDE.md` — never contradicts it.

## How this file gets loaded

`CLAUDE.md` → `@.claude/machine.local.md` (gitignored, one import line) → this file. A fresh clone has
no `machine.local.md` and loads **no posture, silently** — hence the trunk's tripwire.

## Deploy handshake (manifest → confirm → record)

- Every deployable change ends with a **numbered, ordered DEPLOY block** in its task file
  (`board.py --update <id> --manifest @file`). DB steps are numbered in position; callees first.
- ⛔ **A condition that gates the deploy goes IN the block** (`0. WAIT — …`), because the owner acts on
  the board's Deploy Ledger, not the chat.
- ⛔ **Push and pipeline tag only after the owner types `deploy` in THIS session** — enforced by
  `tools/hooks/deploy_gate.php`. Refused → ask in one line, never route around it.
  `decisions.md#deploy-gate-hook`
- **Default to NOT-deployed** until the deploy is confirmed on the server, never by behaviour.
- The only SSH an agent runs is the read-only forced-command host (`tools/hooks/ssh_guard.php`).
  `decisions.md#agent-ssh-is-a-forced-command`

## Work Tracker — `.claude/pending/`

- **Session start: `python tools/board.py`, then read `.claude/pending/pending.md`.**
- ⛔ **Reading the board is NOT permission to start — even for an item named by id.** Open-ended ask →
  top 3–5 candidates with `#id`, recommendation first, then wait. Named item → state the plan, wait.
  ⭐ Exception: bucket E chores (`board.py --chores`). `decisions.md#bucket-e-chores-are-pre-authorized`
- ⭐ **BEFORE the first edit, claim it**: `python tools/board.py --claim <id>`. Unshaped work:
  `board.py --new-provisional "<title>"`.
- `inbox.md` is **the owner's**; write only the `tasks/*.md` your work touched; never hand-edit `pending.md`.

## Wrap-up: what finishing a task actually means

0. **Precheck**: `php tools/precheck.php <every manifest path>`. ⛔ `FAILED` → no hand-off.
1. **Commit ALL your work**, `#<id>:` subject. `php tools/my_changes.php --session <id>` must exit 0.
   The Stop hook `wrapup_guard.php` checks it.
2. **Hand off the deploy, or say "no prod deploy needed."** ⛔ Silence is neither.
3. **Docs/memory pass — before you say "done".** Record what a later session would otherwise
   re-discover, or say "no doc update needed".
4. ⛔ **End on the ITEM's status, as the LAST line.** `**#N is DONE.**` or
   `**#N is NOT done.** Next: <step> — <who>.` A passed check, merge or commit is a STEP, not the item.

## Working in a worktree

Board items that change app code get their own git worktree and test site, so concurrent sessions
cannot break or sweep up each other's half-finished edits. Commit to `task/<id>` only; never merge
into main yourself — end with "Ready to merge: say `merge #<id>`."
